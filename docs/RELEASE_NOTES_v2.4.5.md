# Trae 签到助手 v2.4.5 Release Notes

## 这次修的是什么

**自动签到偶发 `HTTP 429` / `code=3004`。**

典型日志：

```text
result=签到失败：服务端异常（HTTP 429）（code=3004）
device_id=3629128303173945
device_src=manual
device_rotated=false
req_source=2
```

这个报错不是账号、设备号或签到逻辑坏了，而是**请求太密**：

- 09:00 定时签到、首次打开自动签到、手动「一键签到」或补签，可能在几秒内同时触发；
- 同一账号被重复 `claim`，上游按账号 / IP 限流，返回 429 / 3004；
- 旧版对 HTTP 429/5xx 只做一次请求，直接记失败，不会自动补签。

对照原版客户端：Trae 桌面版用全局签到锁串行执行，且对瞬时错误只做 2 次尝试、20 秒退避；原版 WorkBuddy 安卓端用单账号 `RUNNING` 集合去重。本项目 2.4.4 及更早缺少这两层保护。

## 更新内容

- **全局签到轮互斥**：定时、补签、首次打开、手动签到同一时间只允许一轮；
  手动抢不到锁提示「签到进行中」，定时抢不到锁顺延并保留下一天的闹钟。
- **单账号 RUNNING**：同一账号不会被两个入口同时 `claim`，避免重复请求。
- **瞬时错误退避**：网络错误与 HTTP 408 / 429 / 5xx 改为最多 2 次尝试，间隔 20 秒 + 抖动；
  不再做 3 次密集重试，避免加深限流窗口。
- **可重试归类**：HTTP 429、`code=3004`、「当前参与用户太多 / 频繁 / 限流」归为 `retryable`，
  不记终局失败，交给 15 / 30 / 60 分钟补签。
- **通知**：区分「网络或限流异常，签到待补」「第 n/3 次补签」「已达补签上限」。
- **错误归类**：429/3004 归为可重试，不再记终局失败；日志保留原始消息与 `code`，便于区分限流与真正的账号/设备失败。
- **未变**：登录、设备号绑定、签到请求体、积分、设置与界面保持 2.4.4 行为。
- **签名未轮换**：证书与 2.2.0–2.4.4 一致，可直接覆盖安装。

## 安装

- 下载 `TraeCheckin-2.4.5.apk`，要求 **Android 7.0+（minSdk 24）**。
- **可直接覆盖安装 v2.4.4 / 2.4.3 / 2.4.2 / 2.4.1 / 2.4.0 / 2.3.0 / 2.2.0**：
  账号、签到记录、手动设备号与设置全部保留，无需卸载。
- 从源码自行构建、未使用原私钥签名的 APK 签名不同，需先卸载旧版（会清空本地数据）。

## 如果当天已经失败

- 升级到 2.4.5 后，稍等 15 分钟会自动补签；也可以直接手动「一键签到」。
- 不要连续快速点「一键签到」：上游限流窗口内重复请求只会继续 429。
- 如果多个账号同时签到，2.4.5 会串行执行，不会再把同一账号重复提交。
