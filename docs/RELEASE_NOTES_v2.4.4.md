# Trae 签到助手 v2.4.4 Release Notes

## 这次修的是什么

**重新登录后账号从「能签到」变成 `9074`。**

2.4.3 及更早版本在重新登录时会重新生成一个自动设备号，把账号原来绑定、原本能用的
`device_id` 换掉。上游只认第一次登录时注册/绑定的号，新自动号会被设备校验拒绝：

```text
result=签到失败：设备校验未通过（9074）
device_id=6226444625528356
device_src=auto
device_rotated=true
```

而没有重新登录的旧账号一直用原设备号，所以仍然正常。这不是 2.4.3 网络更新的问题，
是「重新登录换号」这个旧行为被触发。

## 更新内容

- **重新登录不再换号**：重新登录时原样沿用账号已有的 `device_id` 与 `machine_id`，
  手动号、自动号都沿用；只有新账号才生成新号。
- **设备号锁定**：新增 `device_id_verified`。第一次成功领取后把当前设备号标记为已验证；
  之后遇到 `9074` 绝不自动换号，改为提示用户设置设备号。
- **首次安装**：第一次登录生成唯一 12~20 位纯数字设备号，第一次成功领取后锁定；
  之后重新登录、定时签到、补签都继续使用这个号。
- **旧账号兼容**：旧版账号 JSON 没有 `device_id_verified` 时，合法设备号视为已验证，
  避免升级后第一次 `9074` 就把历史账号的可用号自动换掉。
- **写库不变量**：`AccountStore.update` 在设备号变化时强制清零 `device_id_verified`；
  新增 / 导入账号只接受合法且不撞号的设备号，避免 `9095`。
- **日志**：新增 `device_verified` 字段，方便判断当前号是否已经成功领取过。
- **未变**：登录页面 UI、签到请求、网络重试 / 自动补签、积分、日志、设置与界面保持 2.4.3 行为；
  本次只调整设备号与重新登录的绑定策略。

## 如果你已经中招

如果已经在 2.4.3 重新登录并稳定 `9074`：

1. 升级到 2.4.4。
2. 账号卡片菜单 →「设置设备号」，填入**重新登录前的旧设备号**
   （日志里 `9074` 之前那条的 `device_id`；例如本次反馈中的 `3629128303173945`）。
3. 保存为手动号后，再点一次「重新登录」，让新 token 重新绑定到旧号。
4. 再点「一键签到」。

如果旧号也不被上游接受，只能填入电脑版 TRAE 的真实设备号。

## 安装

- 下载 `TraeCheckin-2.4.4.apk`，要求 **Android 7.0+（minSdk 24）**。
- **可直接覆盖安装 v2.4.3 / 2.4.2 / 2.4.1 / 2.4.0 / 2.3.0 / 2.2.0**：
  签名证书与旧版一致，账号、签到记录、手动设备号与设置全部保留，无需卸载。
- 从源码自行构建、未使用原私钥签名的 APK 签名不同，需先卸载旧版（会清空本地数据）。
