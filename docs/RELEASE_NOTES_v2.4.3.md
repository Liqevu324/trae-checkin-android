# Trae 签到助手 v2.4.3 Release Notes

## 这次修的是什么

v2.4.2 及更早版本在「自动签到（首开 / 定时）」遇到网络抖动时，会出现下面这类日志：

```
09:07:55  网络错误：Unable to resolve host "api.trae.cn": No address associated with hostname
22:14:34  网络错误：failed to connect to api.trae.cn/... (port 443) after 15000ms
22:14:35  网络错误：thread interrupted
```

这三条不是三个独立 bug，而是同一条链路上的三层问题：

1. **设备当时确实没有真正可用的外网**（连上了 Wi-Fi，但热点没通外网 / 刚切换网络 / 夜间 Wi-Fi 休眠）——
   DNS 解析和 TCP 连接失败都是它的直接表现，App 无法凭空修好；
2. **旧版没有为这种情况留后路**：一次失败就结束，既不等待网络就绪，也不安排补签，
   于是这一天就漏签了；
3. **`thread interrupted` 是旧版自己造成的**：签到线程跑在页面线程池里，
   退出页面 / 销毁 Activity 时调用了 `executor.shutdownNow()`，把正在联网的线程中断了。
   这条日志与网络无关，属于误伤。

v2.4.3 修的是第 2、3 层，并把第 1 层的影响降到最低。

## 更新内容

**网络韧性（本次核心）**
- 新增 `NetHelper`：签到前先做网络可用性预检，断网时最多等 15 秒等系统恢复网络，
  预检通过后仍以真实 HTTPS 请求结果为准，不用预检结果伪造签到结论
- 网络层有限重试：状态查询与领取在纯网络错误（DNS / 连接 / 超时）时最多尝试 3 次，
  退避 3 秒 / 8 秒；HTTP 错误与业务错误码（1001 / 9074 / 9095 等）**不重试**
- **失败自动补签**：定时签到因网络失败时，自动安排 15 分钟 → 30 分钟 → 60 分钟后各补签一次，
  最多 3 次，跨越约 1 小时 45 分钟；补签使用独立 action 与请求码（1003），
  不会覆盖第二天的正常闹钟
- 补签前会先读 `status`，当天已经签到的账号不会重复领取（`claim` 本身也按天幂等）
- 多账号场景下，第一个账号就判定网络不可用时，剩余账号不再逐个空等超时，
  统一交给补签闹钟处理
- 通知文案区分「网络异常，签到待补」「第 n/3 次补签」「已达补签上限」，
  不再把断网笼统显示成「签到失败」

**后台执行可靠性**
- `CheckinReceiver` 改用 `goAsync()` 并在后台线程持 20 分钟 `PARTIAL_WAKE_LOCK`，
  避免 `onReceive` 返回后进程被系统回收导致签到半途而废
- 每日闹钟执行完仍在 `finally` 中强制重排下一天，补签闹钟不参与这次重排

**修复**
- 修复退出主界面时 `executor.shutdownNow()` 中断联网线程造成的 `thread interrupted`
  （改为 `shutdown()`：停止接收新任务，允许已在执行的任务跑完）
- 网络错误与业务错误在引擎层彻底分开：网络类失败带 `network_error` / `error_type=network` 标记，
  签到日志按 `net` 标记展示，不再被记成「领取失败」
- `claim` 返回成功但回查 `status` 时断网的情况，不再直接判失败，而是标记为网络待回查
- 新增 `ACCESS_NETWORK_STATE` 权限（仅用于读取网络状态，不采集任何信息）

**未变更**
- 登录、凭证刷新、设备号校验（9074 / 9095 / 1001）、积分明细、日志、设置项与界面保持 v2.4.2 行为
- **签名私钥未轮换**：证书与 v2.2.0 / 2.3.0 / 2.4.0 / 2.4.1 / 2.4.2 完全一致

## 已知限制

- 如果手机在夜间进入 Doze 且 Wi-Fi 被系统休眠，补签闹钟唤醒时网络仍可能不可用；
  把本应用加入「电池优化白名单」可显著提高后台签到成功率（设置页 → 后台与权限）
- 若某个网络环境下 `api.trae.cn` 长期被 DNS 污染 / 劫持，App 侧无法绕过，需要更换网络

## 安装

- 下载 `TraeCheckin-2.4.3.apk`，传到手机安装；要求 **Android 7.0+（minSdk 24）**。
- **可直接覆盖安装 v2.4.2 / 2.4.1 / 2.4.0 / 2.3.0 / 2.2.0**：签名证书与旧版一致，
  账号、签到记录、手动设置的设备号、设置全部保留，**无需卸载、无需重新登录**。
- 从源码自行构建、且未提供原私钥的版本签名不同，需先卸载旧版再安装（会清空本地数据）。
