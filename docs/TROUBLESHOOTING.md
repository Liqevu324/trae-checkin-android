<a id="login"></a>

## 登录与授权页

- 点右上角「+」，按正常流程用手机号 + 验证码登录；登录检测器响应可能稍慢，等一会儿，或换一个更稳定的网络（例如移动数据）。
- 登录完成后，必须点击绿色的「登录并打开 TraeWork」，不要点「使用其他账号登录」或「取消」。
- 第三方登录（抖音 / 苹果 / 企业账号）可能走 `window.open` 弹窗；如果弹窗不可见，改用手机号 + 验证码。
- 如果页面提示「网页脚本未能运行」，先更新「Android System WebView」或 Chrome；仍不行时，长按「重新发起登录」复制诊断信息（含 `js_patch` 与报错位置）。
- 登录页频繁黑屏 / 空白：先在系统设置里清除 WebView 缓存，或换网络重试。

<a id="9074"></a>

## 9074 设备校验未通过

- `9074` 不是登录失败，也不是 token 失效；它是上游对 `X-Device-Id` 的独立设备校验。用无效 token 实测 `claim` 返回 `1001`，不是 `9074`。
- 处理：账号卡片菜单 →「设置设备号」，填一个 **12~20 位纯数字**设备号。**只需设置一次**；手动号会被标记为 `manual`，`9074` 时不会自动轮换，重新登录也不会覆盖。
- 一个设备号一天只能签一个账号；多账号请分别使用不同设备号。保存时会检测撞号。
- 仍失败时，确认使用的是 v2.3.0 及以上版本；不要额外发送 `x-device-brand` 等与授权页声明矛盾的指纹头。
- 设备号原理与请求契约见 [ARCHITECTURE.md](../ARCHITECTURE.md) 的「登录」与「9074」章节。

<a id="9095"></a>

## 9095 当前设备今日已签到

- 含义：这个设备号今天已经签过，可能是同设备的另一个账号。
- 处理：换一个设备号；或确认该账号今天是否已经签到。不要反复重试。
- 多账号场景下，每个账号应使用独立设备号；同号会触发 `9095`。

<a id="1001"></a>

## 1001 / 登录过期

- 含义：访问凭证过期或无效。
- 处理：账号菜单 →「重新登录」。App 会先用保存的 `refreshToken` 续期，失败后再走授权页。
- 如果频繁出现 `1001`：检查系统时间 / 时区是否正确；确认账号没有在 Trae 侧退出登录或修改密码。
- 旧账号仍保留 cookie 兜底路径，但推荐重新登录走 SOLO OAuth。

<a id="9004"></a>

## 9004 设备未注册

- 含义：设备号没有随授权页注册到上游。
- 处理：重新登录一次，让授权页重新绑定设备；仍失败时手动设置设备号后再登录。
- 账号会保存并显示具体原因，不会因为一次 `9004` 白登录。

<a id="network"></a>

## 网络与补签

- v2.4.3 起：签到前用 `NetHelper` 预检网络，断网最多等 15 秒；`status` / `claim` 遇 DNS、连接失败、超时最多 3 次（退避 3 秒 / 8 秒）。
- 定时签到因网络失败时，会在 15 → 30 → 60 分钟后自动补签，最多 3 次；补签前先查 `status`，已签到不会重复领取。
- `thread interrupted` 是 v2.4.2 及更早版本退出页面时 `shutdownNow()` 造成的假错误；v2.4.3 已改为 `shutdown()`。
- DNS 解析失败 / 连接超时：换网络（移动数据或其他 Wi-Fi）；检查 VPN、代理、私人 DNS、企业网络限制。
- 如果某个 Wi-Fi 长期解析不了 `api.trae.cn`，App 侧无法绕过 DNS 劫持 / 上游故障，换网络即可。
- 手机深度休眠（Doze）时系统会限制后台网络；把 App 加入电池优化白名单可以显著提高成功率。

<a id="background"></a>

## 定时与后台

- 检查 App 内：设置 → 自动任务 → 每日自动签到是否开启；签到时间是否正确；账号是否被排除。
- 检查系统：允许自启动、后台运行、关闭电池优化；国产 ROM 的通用路径见 [兼容性说明](COMPATIBILITY.md)。
- Android 12+ 需要「闹钟和提醒」权限；没有精确闹钟权限时，系统可能延迟触发。
- 开机 / 应用更新后，`BootReceiver` 会恢复闹钟；如果被系统限制，打开一次 App 也会重新排程。
- 仍然不执行：长按日志复制，检查是否有 `9074` / `9095` / `1001` / 网络错误；必要时重新登录。

<a id="notifications"></a>

## 通知

- Android 13+ 需要 `POST_NOTIFICATIONS` 权限；在系统设置 → 通知中允许本应用。
- 检查通知渠道是否被设为「静默」或关闭；App 内「通知提醒」开关是否开启。
- 定时任务被系统杀掉时不会有通知；先解决后台权限。
- 补签通知会区分「网络异常，签到待补」「第 n/3 次补签」「已达补签上限」。

## 日志与反馈

- 长按单条日志可复制完整报错：`app_version / account / time / result / code / remaining / device_id / device_src / req_source`，**不含** token、refreshToken、cookie 或完整响应体。
- 反馈时请附：版本号、Android 版本、ROM、错误码、日志文本。
- **不要**发送账号密码、完整 token、`refreshToken` 或导出的账号 JSON。
